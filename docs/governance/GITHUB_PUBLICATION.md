## 主仓库：普通非敏感资料自动检查后直接上传

通过合法的 HTTPS 或 SSH origin、远端 `owner/repo` 和仓库 ID 双重核对目标，检查仓库当前可见性、实际账号及操作权限。2026-11-01 曾观察到该仓库为 public，之后必须重新读回；public 的任务分支同样可公开读取。禁止把客户内部资料、含敏感或私有内容的内部同步包、私人录音、合同、敏感商业记录、私有 Drive 索引、受限制书籍原文或凭据推到公开仓库。匿名 API 无法读取私有仓库时，应使用授权连接器核验，不能凭 404 断言不存在。

普通项目说明、研究摘要、代码、配置模板、知识卡和已脱敏测试，以及内容非敏感且有使用权的 DOCX、PDF、XMind 等原格式资料，均可进入主仓库。逐文件审查由执行器自动完成，不等于要求用户逐文件再批准；“项目内部使用”不自动等于敏感。只有发现凭据、客户隐私、合同、敏感商业记录、私有入口、受限原文、明确保密分类，或内容确实无法读取/授权不清等具体问题，才暂停相关文件并给出脱敏或补证动作，其他普通文件继续。保留原格式及正式源/镜像说明；不自行改仓库可见性、协作者或共享权限。

自动预检至少核对真实路径、限定文件范围、Git忽略规则、大小、文本/容器内容、敏感文件名及高置信凭据模式。使用仓库 `scripts/check_project_upload.py --repo <仓库根> <明确文件路径...>`，输出状态、SHA和原因，不输出疑似密钥值。启发式检查不是绝无隐私泄漏的证明；扫描版/加密/损坏或含未能检查附件的文件应具体报告覆盖缺口，不能一概把扩展名列为禁止。发现疑似历史泄露不能用 `.gitignore` 当撤回工具。

Markdown和UTF-8代码可用正常Git或文本接口；DOCX/PDF/XMind原文件使用正常Git，或base64 blob → tree → commit，不能把二进制塞入只接受UTF-8的create_file/update_file。超过网页25MiB限制改用Git，不认定仓库无权限；超过普通Git单对象100MiB须先配置并上传真实Git LFS对象，不能只提交虚假指针。50MiB以上建议LFS评估。LFS仅在实际需要时用项目本地配置，不改用户全局设置、不迁移旧历史、不绕过敏感保护；无法使用时只阻断相应大文件并报告。上传与回读方法见仓库 `docs/governance/UPLOADS.md`。

## 本地 Git 纪律

开始前检查 `pwd`、Git 根和元数据位置、origin、分支、`git status` 以及远端当前状态；对用户未提交或未跟踪内容保留原状。不得盲目 `pull`、切换分支、`reset`、`clean`、`stash`、强推、改写历史或覆盖他人工作。共享工作树 Git 操作遵守 07 的协作锁；锁不能约束不使用它的进程。

普通非敏感资料通过检查且任务没有指定其他分支时，默认可直接向 `main` 正常快进提交/推送，无须另开分支等待批准；需要隔离的功能开发、实质改线或冲突仍可用任务分支。只按明确路径暂存，禁止 `git add .`。提交前检查差异、敏感性、忽略规则、大小及适合改动的验证，保护既有未提交工作。

发布前重新读远端目标HEAD；普通Git只允许正常快进，禁止force和force-with-lease。连接器按目标当前树创建提交、父提交使用实读HEAD，更新ref时使用该 `expected_sha` 且 `force=false`。远端有并发变更时重读，保留对方变化；同路径冲突不能静默覆盖。不要借普通资料持续授权自动合并无关功能分支。仅Drive且无需仓库记录的文档任务不制造Git提交；应入库普通项目资料按本授权执行。

正常快进也可能带入当前分支上的其他提交。推送HEAD前须验证实读远端HEAD为本地HEAD祖先，检查 `git log <remote-head>..HEAD` 及其完整累计diff均在本任务授权文件范围；含无关历史时不得整支推送，应基于实读目标树构造限定变更提交，不能擅自改写、清理或覆盖用户工作树。

推送后回读目标分支SHA及具体文件内容/原始字节SHA，不能只看提交成功消息。连接器可正常写入时，本机gh未登录不是全局上传阻碍；本机Git与连接器权限分别报告，不索取或打印令牌。本地文件、提交、推送、main采用及业务验收仍分别验证。

## 甲方仓库：默认关闭，选择性发布

甲方仓库地址、账号权限、允许路径、目标分支、发布文件白名单、审核人和明确发布授权全部具备前，不接入、不克隆、不推送、不创建 PR，也不能把历史直播仓库当甲方仓库。各参数以当前实际授权为准，不从仓库名字推断。

条件具备后按「内部开发 → 内部验收 → 选择性导出 → 甲方任务分支 → 审核 → 发布确认」执行；重新读取甲方仓库规则、确认 owner/repo 和授权路径、检查文件与敏感性，遇规则或权限冲突暂停相关发布。不要配置双推地址、镜像整个内部仓库或直接推送全部历史。内部分析、费用底稿、录音、凭据、未授权知识原文及开发日志不随成果外发。确需本地克隆时仅放工作区内受控发布区，并从主仓库追踪中排除，避免误提交嵌套仓库。

提交、推送、合并或放入交付区都不等于甲方收到、采用或验收。逐项保留目标、版本、文件白名单、审查、发布与回读证据，未执行或无法验证的步骤明确标记。
