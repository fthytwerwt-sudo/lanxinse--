# V3 公开机制入口

版本 V3.0 / 2026-11-01。此文件只承载适合公开的协作原则；内部机制、私有目录索引和执行证据保存在授权受控位置。仓库默认分支是否采用本版须以实际分支和提交为准。

1. 先识别真实目标、任务阶段、材料及权限。复杂任务核对目标、机制、实现设计、流程、判断标准、反馈；设计包含主/备路线、实际能力、最小probe、输入输出、入口、验证、授权和停止线。已明确授权的安全步骤直接执行，简单问答不强制工程流程。
2. 跨账号任务全文包含 Goal、Context、Current State、Constraints、Inputs、Implementation、Execution Steps、Outputs、Acceptance、Blocked If、Feedback，附任务及机制版本、必要可读材料。不得依赖未知聊天历史，probe通过不自动扩大权限。
3. 已确认、部分成立、待验证、推测、通用建议、blocked按证据和范围使用。保留原始材料、观察、用户转述与推断分层；遇冲突查对象/时间/版本，保留反方证据。按原任务→产物→证据→验收决定通过、修正、降级、改线或阻断，无新证据不反复推翻方向。
4. 项目本地写入限授权工作区；文件、临时、缓存、备份和工作树同样受限。新执行器先验证实际环境，Work云端不冒充本地挂载。规则和协作检查不能证明操作系统硬隔离。
5. 正式来源按用途区分：允许公开的代码/模板适合本仓库；客户方案和内部材料留授权私有存储；Project保存安装后的机制副本。普通讨论不逐条建文件，正式成果按授权查重归档和回读，不创建后台同步。
6. 公共仓库的任务分支仍公开；发布须检查身份、可见性、权限及白名单。甲方发布参数和授权不全时关闭，仅在授权后选择性导出，不镜像内部历史，不更改共享或自动合main。
7. 评论研究、视觉浏览、知识库和文案仅在对应任务触发。原评论、来源、去重、样本限制和人工审核不能由AI生成替代；不绕验证码。用户授权写作或知识库开发时按本轮目标执行，不受旧全局评论阶段限制。
8. 保留历史原文及可恢复备份，旧版本不与新版本混合执行。每次机制更新记录差异和回归，Project安装、Work读取、Git推送及main采用分别验证。公开入口不能代替访问完整内部机制的必要授权。
